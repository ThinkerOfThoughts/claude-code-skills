## Part C — Oracle-can-fail self-test (gates every Part-A result)

**Pass 1's design was tautological and is replaced.** Reviewer B-F07: `check.sh`'s assertions are
literal/normalized string probes, and pass 1's mutant was "delete the text the assertion asserts". *A
string probe always fails when its string is deleted.* The mutant set would have returned **100% KILLED by
construction**, proving nothing about whether a probe checks a **rule** or merely a **phrase** — the
bare-`exit 0` defect one level up, in the very instrument built to prevent it.

| ID | Criterion | Label |
|---|---|---|
| **C-M1** | **Semantic mutants.** For each assertion, `oracles/mutation-test.sh` **will generate** mutants that change the rule's **meaning** while leaving recognisable text: **(a) negate** it (invert the obligation); **(b) swap its actor** (a reviewer duty reassigned to the author); **(c) move it out of its governing section**; **(d) weaken it to a hedge** ("should where practical"). Each mutant **must be** KILLED by its assertion. A **surviving** mutant would mean the probe matches a phrase, not a rule; the probe **will be** rebuilt. | gating |
| **C-M2** | **Insertion mutants for the absence sweeps.** C-06b, C-09b and C-16b assert **absence**, for which deletion is undefined — the correct mutant is **insertion** of the forbidden text (a licensing sentence; a "~85%" statistic; a draft banner). Each sweep **must** FAIL on its insertion mutant and **PASS** on the clean file. | gating |
| **C-M3** | **Negative control.** The mutant set **will include** ≥1 mutant whose expected outcome is **SURVIVED** (a deliberately un-asserted span), so the harness is observed printing a non-kill. A harness that has only ever printed `KILLED` has not been shown able to report a failure. | gating |
| **C-M4** | **The self-test's own invocation is pasted verbatim** into `8-harness.md`, arguments included, with the exact output of the clean run and of every mutant run. | gating |

**Honest statement of a limit, per the escalation standard.** Reviewer B judged the absence sweeps to have
**no possible mutant shape**, which would have made C-06b/C-09b permanently unverifiable and forced a halt.
On checking, that is **not** correct: an absence sweep has a well-defined mutant — **insertion** — and B's
own text names it. C-M2 implements it. **No gating criterion in this document is unverifiable pre-ship.**
If any turns out to be during the build, `8-harness.md` will say so plainly and mark it unverifiable rather
than report a pass, and that is a stop-for-human.

**`check.sh` hygiene (planned).** It **will refuse** to run with no argument and **will return** a **usage exit
code distinct from a clean pass**, so a no-argument invocation cannot be misread as a pass — this project once "verified" a
checker exactly that way.

**Until C-M1–C-M4 have run and their output is pasted, every Part-A criterion is `verified = no`** (H6,
ST1.5f) — including ones that would otherwise look green.
