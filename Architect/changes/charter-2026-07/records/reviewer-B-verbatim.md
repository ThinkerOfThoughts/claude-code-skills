## Lens 2 — Logical

**F-01 · blocker · `1.5-criteria.md` C-17 + B-1; `2-plan.md` §1.1 row 3, §3 "H3 compliance".** **The run's only position criterion is verified by an experiment that cannot vary position.**

C-17 is gating and self-describes as the position criterion. Its text half is disclaimed as insufficient — correctly, citing ST1.5d and H3. Its "executed half" is B-1. But B-1's arms are: HOLED = "a plan containing a step **above** the floor"; INTACT = "the **same** plan with that one step rewritten to sit **at** the floor; everything else identical" (`1.5-criteria.md` Part B). **Both arms receive the same charter, with the floor in the same place.** The only variable is the fixture's vagueness. B-1 therefore measures whether the floor's *content* discriminates — it produces no evidence whatsoever about whether the floor's *position before the lens block* matters. B-1's own criterion line claims it tests "the floor's *position and content*"; there is no positional variable in its design.

`stage-8.md` L25–31 (H3): a position criterion "is satisfied **only** by running its isolating case and observing the behavior occur." `stage-1.5.md` L62–76 (ST1.5d): the criterion must "assert that the *behavior* which depended on **the arrangement** is preserved… tested on a case that exercises *only* that path." B-1 exercises the floor-content path, not the arrangement path. `2-plan.md` §3 asserts "**H3 compliance**" for exactly this pairing — the plan claims conformance with the rule it violates.

Failure scenario: the harness runs B-1, HOLED files "you didn't say how", INTACT does not, C-17 is marked verified, and the run ships a charter whose central positional design decision (`2-plan.md` §1.1 row 3: "**Before the lenses, deliberately**") has never been tested. If the position is in fact inert, the run has manufactured a false positive on the one criterion the position lens forced into existence.

The fix is already in the author's own toolkit and was not generalized: **B-3/B-4 are charter-ablating arms.** A position arm is the same shape — same fixture, INTACT charter with floor before the lenses, HOLED charter with the floor moved after them. That the author invented charter-variation for two criteria and did not apply it to the one criterion that provably requires it is, again, the D5 under-generalization pattern.

Secondary defect in the same criterion: ST1.5d L74–76 requires that where the effect is probabilistic ("recency/precedence usually shift a *rate*, not flip a switch") the criterion "states the pass rate it expects and the number of runs that establishes it… rather than relying on a **single probe**." C-17/B-1 is a single probe per arm with no stated rate — see F-08.

**F-05 · major · `0-baseline.md` §0.5 D3; `2-plan.md` §8 R4.** D3's stated rationale does not support its conclusion, and its resolution relocates the problem to a strictly narrower signature.

D3 reasons that adding parent-plan/seam to every plan red-team is "an un-spec'd widening of a signature the owner wrote" — treating `Spawn_redteam(_task, _plan, _granularity)` (`Architect.md` L24) as an exhaustive enumeration of reviewer inputs. If the signature were exhaustive, the charter could not be delivered at all. So the signature is plainly not an input contract, and the argument D3 rests on is unsound as stated.

Worse, the resolution — "state the parent-plan/seam inputs **only for the `Divisible` split-review caller**" — moves the widening to `Divisible(string _task, string _granularity)` (`Architect.md` **L14**), a **two**-argument signature, called as `Divisible(task, granularity)` at L58, L83 and L107. **Nothing in `Divisible`'s call site carries a parent plan.** The seam is derivable (it is a property of the division `Divisible` itself produces, and `Human_gate` presents "the seam between the halves" at L16); the parent's plan is not. **F-07 · major · `1.5-criteria.md` Part C; `2-plan.md` §2.3.** The oracle-can-fail self-test is tautological for the checker it gates, and undefined for two of its gating criteria.

`check.sh`'s assertions are literal/normalized string probes (`2-plan.md` §2.2: "one **positive per-site assertion** per row of `rules.tsv` — *the rule IS STATED at the site that must state it*"). The mutation strategy is "copy the shipped charter, **delete the text that assertion asserts**, run `check.sh`, and require that **that assertion FAILS**" (§2.3). A string probe *always* fails when its string is deleted. The mutant set therefore returns 100% KILLED by construction and establishes nothing about whether an assertion checks the **rule** or merely a **phrase**. The negative control (one un-asserted block deleted ⇒ SURVIVED) proves the harness can print a kill-line — it does not break the tautology. The mutants that would actually discriminate are semantic: the rule **reworded**, **negated**, **moved to the wrong section**, or **weakened to a hedge**. None is planned. Given that this project's named failure mode #2 is "a checker that exited 0 on every input, twice," a self-test that cannot fail is the same defect one level up — which is precisely what C-M1's second paragraph claims to guard against.

Second, **the mutation design has no mutant for an absence sweep.** C-06b and C-09b are gating and assert *absence*. Deleting "the text the assertion asserts" is undefined for them; the correct mutant is *insertion* of the forbidden text. Neither `1.5-criteria.md` Part C nor `2-plan.md` §2.3 provides for it. Part C then states: "Until C-M1 has been run and its output pasted, **every Part-A criterion is `verified = no`**." C-06b and C-09b can never satisfy C-M1 as designed, so two gating criteria are permanently unverifiable — which by the criteria doc's own closing paragraph is a **stop-for-human**, not a proceed.

**F-08 · major · `1.5-criteria.md` Part B discrimination rule; `2-plan.md` §4, §6.** Every behavioral arm is n=1, and the sole remedy for a non-result is unbounded and self-administered.

Eight agents, four criteria, **one sample per arm** (`2-plan.md` §4). LLM review output is stochastic, and `FINDINGS.md` F7 (L92–96) is this project's own measurement that same-model instances behave in correlated but not identical ways. No criterion states a pass rate or a run count. ST1.5d L74–76 explicitly forbids relying on a single probe for a probabilistic effect. A B-1 pair that discriminates on one draw is not evidence the charter causes the behavior; a pair that doesn't is not evidence it fails.

Compounding it: the discrimination rule's only branch for a non-discriminating pair is "the fixture is rebuilt (logged in `decisions.md`) and re-run", and `2-plan.md` §6 explicitly rules that this is **not** a routing event and therefore **never counts toward the iteration cap**. So the runner may rebuild fixtures without bound until a pair discriminates, and the rebuild is judged by the runner. For B-2 this converts the criterion from "the charter causes tier-(iii) behavior" into "the runner eventually found a hole blatant enough that any reviewer would flag it" — a **proxy pass**. This is attempt-1 failure mode #6 (`ATTEMPT-2-STATE.md` §8: "A gate satisfiable by the party it constrains") reproduced structurally, in the run that lists it as a thing to hunt.

**F-09 · major · `1.5-criteria.md` Part B "Declared deviation"; `2-plan.md` §4, §1.1 row 7.** The ablation is never diffed, and its deletion target is bundled with unrelated rules.

On the deviation itself: the config's `check.how` (4) words the arms as "a HOLED arm (fixture violating the rule) and an INTACT TWIN (fixture satisfying it)" — fixture-varying — and for (d) it even specifies a fixture ("a defect a reviewer would plausibly assume someone else will catch").
