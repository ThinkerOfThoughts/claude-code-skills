# Stage 1.5 — Acceptance criteria (hardening cycle 2)

**All criteria are GATING unless a row says `advisory` with a stated reason.** Every criterion is
checkable by one of the two admissible means (automated, or a named human-judged rubric).

## How each criterion is verified — and the honest label on the method

Three verification methods appear below, and **each row says which it uses and what that method cannot
see**:

| Method | What it proves | Named limitation (stated, not hidden) |
|---|---|---|
| **P — positive per-site assertion** (`oracles/check.sh`) | the rule **is stated**, in normalized text, at **each site that must state it** | a *text* check. For a criterion whose subject **is** the text (a heading string, an honesty claim, a contract key), P is the criterion, not a proxy. For a criterion whose subject is **behaviour**, P is a **PROXY** and is labelled `PROXY` — such a row must also carry an execution arm. |
| **X — execution arm** (two separately-spawned cold agents) | an agent reading only the new stage text **routes a holed fixture differently from its intact twin** | costs 2 agents; the verdict is one agent's judgment, so a *pair* is the unit. **Both arms the same verdict ⇒ `verified = no`**, whichever verdict it is. |
| **M — mutation test of the oracle itself** (`oracles/baseline-replay.sh`) | the oracle **can fail** (H6 / ST1.5f) | proves the checker discriminates; proves nothing about the artifact. |

**M is mandatory for every P row.** `baseline-replay.sh` runs the *same* `check.sh` against the baseline
tree materialised from `git show b08f5a9:Architect/*`. **Every new-rule assertion MUST FAIL there** and
**every preserved-rule assertion MUST PASS there.** A `check.sh` subcommand that passes against the
baseline is **not an oracle** and its criterion is `verified = no`. *(Cycle 1's three instruments each
failed this test; this is why it is a hard gate here.)*

**A "mention" check is not a read/write check.** No row below is satisfied by `grep`ing that a *word*
appears. Each P assertion names the **operative sentence** it requires at each site, matched on
**normalized** text (strip `**`/`*`/backticks, collapse whitespace, flatten line wraps), and any absence
sweep is **paired** with its positive assertion.

**No "declared deferral" route exists.** A gating criterion that cannot be verified pre-ship has exactly
two legal dispositions (`Guarded_change/stages/stage-8.md` H5): a representative pre-ship harness, or a
**named risk-acceptance** in `decisions.md`. Under RAT3 nobody present can grant the latter, so the third
and only remaining move is **HALT + verbatim relay to the orchestrator**. This runner will do that rather
than record a deferral.
