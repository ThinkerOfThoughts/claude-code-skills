# Criteria (all gating; proof home for every one: a stage-8 one-off check recorded in 8-harness.md, because the subject is prompt text, not code)

C1. Every cold-reviewer sign-off at stage 3 and stage 6 states, via the charter, that the pass means the artifact meets every
    principle of the project's principles sources and every prior owner decision in the inputs. A violation ranks at least
    MAJOR. The reviewer renders a per-entry verdict (meets / violates / n.a.) with the line that shows it. A record missing the
    section is un-run for that duty.
    Check: read charter.md, stage-3.md, stage-6.md for each clause; plus C5.
C2. The check covers omissions and existing code: for each operation the change performs (read, write, append, delete, ...)
    the reviewer names the existing shared mechanism it goes through, found by searching the source; a hand-written duplicate
    of an existing shared mechanism, or a shared mechanism worked around because it almost fits instead of being extended,
    is a violation; scope declarations ("not edited", "out of scope") and clean mechanical guards are claims to challenge.
    Check: read charter.md; plus C5.
C3. The config contract has an optional `principles_context` slot (principles sheet and prior-decision sources); when the
    config names it, it is a required reviewer input at stages 3 and 6, is validated like `redteam_context` (CFG3, gate 4),
    joins the closed input set and the reported-hash list. `guarded-change.companion.md` names the companion principles
    sheet there. No project-specific text appears in charter.md or stage files.
    Check: commands and known-bad self-test in 2-plan.md "Measurement" (grep over the ADDED lines only; the pre-existing
    companion config text is out of the check's scope).
C4. Structure: the charter holds the conformance duty once; stage-3 and stage-6 add only their stage-specific scope plus the
    up-front "require the labelled section" clause and do not restate it; SKILL.md, METHODOLOGY.md and the stage files agree
    on the input list and on the existence of the duty; the five-lens requirement (CH13/ST6e) is unchanged.
    Behaviour preservation (position-sensitive assembly, ST1.5d), verified by EXECUTION in the C5 record: the reviewer still
    emits all five labelled lenses, a coverage-challenge section, a label audit with per-criterion evidence, and fidelity
    pins; the tail bullet does not crowd them out.
    Check: commands in 2-plan.md "Measurement" (input-list greps, single-definition grep) plus the C5 record.
C5. Regression replay (one end-to-end run): one cold sonnet reviewer, given the NEW charter and stage-3 file, the failed
    run's original `2-plan.md` and `1-spec.md`, the principles sheet, and a facts file (the shared module has `append_jsonl`,
    `iter_jsonl`, `parse_jsonl`, and no delete function), raises the hand-written reader and/or the bare unlink as a P1/P7
    violation at MAJOR or higher, and its record carries a Principles-and-decisions conformance section with per-entry verdicts
    with lines and a mechanism table with file:line. Fails otherwise. Count rebuilds of the test mechanism; past three, stop and report.
C6. Housekeeping: the ADDED lines contain no personal names and no absolute home paths; installed copy `diff -rq` against the repo shows only repo-only differences; `Plan_ledger/` untouched.
