# Stage 1.5 — Criteria: the measurable accept bar

Seeded from the approved plan's **Verification** section (6 items) + the standing **skill
self-check** criteria (the artifact under change is a skill = a position-sensitive prompt
assembly, so the self-check set from `guarded-change/stages/stage-1.5.md` applies as gating
criteria). Each criterion is checkable; each is labeled **gating** (must be verified by
execution at stage 8 for accept) or **advisory** (surfaced, non-blocking) with a reason.

Verification model for a **skill** artifact: a criterion is verified either by (i) **execution**
— walking the skill on a tiny fabricated synthetic corpus and observing the governed behavior
occur (a route-(a) representative pre-ship harness per the config's stage-8 `check`), or (ii) a
**document invariant** — a positive per-site assertion across the skill files that a rule is
stated and internally consistent, self-tested to be able to fail (H6/ST1.5f). Behavioral criteria
(blindness, restart, cut-gate, concurrency) require **execution**; a pure re-read of the docs does
not verify them (CP6/H3 — text-presence is exactly the check a prompt-behavior change can defeat).

---

## C1 — Blindness (gating)

**Claim.** When the skill is walked, a coordinating node's own actions **never open findings
content** — it opens only each direct child's `_status.md` and globs child dir/filenames; it never
`Read`s any `analysis/*.md`, `*_verified.md`, `superlist.md`, or `*_summary.md`.

**Verified by execution.** Walk the skill on the tiny corpus; dispatch real analyst leaves for at
least one item so real findings files exist on disk; then inspect the **coordinator's own
transcript / tool-call log** and confirm zero `Read` (or `cat`/`grep -c` for content) of any
findings file, only `_status.md` reads + dir globs. **Oracle-can-fail self-test (H6):** point the
same check at a deliberately-planted coordinator action that *does* read a `superlist.md` and
confirm the check flags it.

**Label reason.** Gating — blindness is the method's core property; a coordinator that reads
findings has contaminated the distillation, defeating the skill's reason to exist.

## C2 — Deterministic restart (gating)

**Claim.** Killing the run mid-stage and resuming re-runs **no completed stage** and loses
nothing: next-step is derivable from disk alone (stage-done-iff-output-exists on deterministic
filenames; trust-files-over-cursor).

**Verified by execution.** On the tiny run, complete a stage (e.g. one item's analysis), simulate
a HARDSTOP (drop in-memory cursor), then re-derive the next action **from the on-disk tree only**
and confirm (a) the completed stage's outputs are detected as done and not redispatched, (b) the
interrupted stage is the only thing re-run. **Oracle-can-fail self-test:** delete one completed
leaf's output file and confirm the resume logic now (correctly) re-dispatches exactly that leaf.

**Label reason.** Gating — the session-limit death was a real production failure; durable resume
is a load-bearing guardrail, not a nicety.

## C3 — Agreement format (gating)

**Claim.** Super-list entries render agreement as **`PCT% (X/N)`** — floored integer percentage
first, then the raw fraction — and the super-list **sorts by percentage desc, then recurrence
desc**; the denominator N (analyst count for the item's tier) rides through merge → summary.

**Verified by execution + document invariant.**
- *Execution (flat merge):* run one real merge leaf on two fabricated verified-analysis lists
  (known overlaps, known N) and confirm the emitted super-list shows `PCT% (X/N)` with correct
  floored percentages (e.g. 2/6 → `33% (2/6)`) and correct sort order.
- *Execution (seam-aware merge — added per stage-3 CH8-2):* run one merge on a **subdivided**
  item's two per-piece verified lists that contain a finding **straddling the split seam**; confirm
  the seam-straddling finding is deduplicated into ONE entry (not double-counted, not dropped) and
  its recurrence/agreement is correct across pieces. This exercises the "seam-aware for subdivided
  items" path (stage-5), which a flat merge does not.
- *Document invariant:* grep every skill file for the agreement-format spec and confirm all
  statements agree (format string, floor rule, sort key, denominator-preservation). **Oracle-can-
  fail self-test:** run the format check against a fabricated `50% (2/3)` (wrong: 2/3 floors to
  66%) and against a fraction-first `(2/6) 33%` and confirm the check flags both.

**A1 caveat (recorded per stage-3).** The binding "N = the item tier's analyst count" is exercised
end-to-end only with fabricated known-N lists, not via a full real tier-6 dispatch (a declared
cost bound); the tier→N binding itself is additionally held by the document invariant (C8 iii).
This is recorded, not hidden.

**Label reason.** Gating — the percentage-first cross-tier comparator + floor rule is an explicit
owner decision (mixed 3-analyst and 6-analyst items must be comparable); getting it wrong makes
the primary deliverable's ranking unsound. The seam-aware sub-check is gating for the same reason:
a mis-merged seam corrupts agreement/recurrence on exactly the subdivided items the cut-gate
exists to protect.

## C4 — Size-strategy routing (gating)

**Claim.** The decompose+size stage routes by *what* is big among **all three** strategies: a
fabricated oversize **binary-bulk** artifact → **replace-with-descriptive-tag** (streaming slimmer,
original untouched); a fabricated oversize **text** artifact → **subdivide** into context-complete
pieces; a fabricated **irreducible** oversize item (analytically-relevant text that does not
cleanly subdivide) → **escalate the model tier** (toward the Opus reserve). Tiers are picked by the
**post-slim token estimate** (not raw bytes).

**Verified by execution.** Fabricate (a) a jsonl whose rows carry a huge base64 blob (binary
bulk), (b) a large plain-text artifact, and (c) an irreducible-oversize item. Walk the size stage
and confirm: (a) routes to tag-replace via the streaming slimmer, original file unmodified
(mtime/size unchanged), slimmed copy in `_prepared/`; (b) routes to subdivide with a split plan;
(c) routes to **escalate-tier** (not mis-routed to Haiku-subdivide); and the tier chosen for each
uses the post-slim/estimated token size, not the raw byte size. **Oracle-can-fail self-test:** feed
a small in-window text artifact and confirm it does NOT route to subdivide, tag-replace, or
escalate (the check distinguishes among all four outcomes, rather than always saying "subdivide").

**Label reason.** Gating — the OOM was a real production failure; mis-routing (e.g. trying to
subdivide a 1.2 GB binary, or `Read`-ing it whole) reproduces the crash.

## C5 — Human cut-gate fires (gating)

**Claim.** A subdivided/borderline item **blocks on human approval** (of atomic unit / split
points / overlap + the context-preservation argument) **before any leaf is dispatched**; a
clean-fit, clearly-tiered item **auto-proceeds** without the gate.

**Verified by execution.** On the tiny run: confirm the oversize-text item (from C4) **reaches the
cut-gate stop and dispatches nothing** until approval is recorded (the governed behavior = the
stop occurring + no dispatch), while a clean-fit small item proceeds to dispatch without stopping.
**Oracle-can-fail self-test:** confirm the check would fail if the subdivided item dispatched
before an approval record existed (plant that state and confirm it flags).

**Label reason.** Gating — a wrong cut wrecks representativeness for the whole item; the plan calls
this "the skill's representativeness gate."

## C6 — Concurrency cap (gating)

**Claim.** A static concurrency budget is computed at decompose-time and **peak concurrent agents
never exceeds** it; dispatch serializes within the cap.

**Verified by execution.** Walk decompose on the tiny corpus, confirm a budget number is computed
and written to `plan/budget.md`, then confirm the dispatch procedure caps in-flight agents at that
number (serialize within cap). **The harness pins the dry-run budget BELOW the walk's offered
concurrency** (added per stage-3 C6 label-audit) — so the cap actually **binds** during the walk
and serialization is *observed*, not merely reasoned about: with multiple ready items/leaves and a
budget of e.g. 2, confirm no more than 2 agents are ever in flight and the rest wait.
**Oracle-can-fail self-test:** set the budget to 1 and confirm the procedure flags a
2-agents-in-flight state as a violation.

**Label reason.** Gating — the OOM headroom is a planned parameter; an uncapped fan-out on heavy
artifacts is the crash path.

## Skill self-check criteria (artifact under change = a skill)

## C7 — live copy == source copy (gating)

**Claim.** The installed skill (`~/.claude/skills/data-distiller/`) is byte-identical to the repo
source (`Data-Distiller/`, excluding the `changes/` provenance folder).

**Verified by execution.** `diff -r` the two trees (scoped to skill content, not `changes/`); zero
diff. **Note:** per the runner's constraints the orchestrator may own the live sync; if the live
copy is not staged at stage 8, this criterion is reported `verified = no` and **handed to the
orchestrator** as the one post-build sync-and-verify step (not silently passed). **Loop-close
(added per stage-3 C7 label-audit):** the hand-off is not complete until the orchestrator's
post-sync `diff -r` outcome is folded back into this run's `8-harness.md` / `decisions.md` — a C7
left at `verified = no` with no recorded orchestrator diff result is an open gating criterion, not
a closed one.

**Label reason.** Gating — a drifted live copy means users run a different skill than the reviewed
one; the whole review is then about the wrong artifact.

## C8 — cross-file rule consistency (gating)

**Claim.** Every rule stated in more than one skill file **agrees** across all statements. The
enumerated shared rules: (i) agreement format `PCT% (X/N)` + floor + sort (covered by C3); (ii)
the blindness rule (parent reads only `_status.md` + globs); (iii) redundancy counts (Haiku=6,
Sonnet/Opus=3; verify one-per-list); (iv) the read-only + off-limits + do-the-work brief clauses;
(v) the size-strategy trichotomy {tag-replace, subdivide, escalate}; (vi) the on-disk layout
names (`tree/`, `summaries/`, `_prepared/`, `config/`, `plan/`, `_status.md`, `superlist.md`).

**Verified by execution (document invariant).** For each shared rule, grep the value across every
file that states it and confirm agreement (a positive per-site assertion — the expected value is
present at each site — not a bare absence sweep). **Oracle-can-fail self-test:** plant a
contradictory value (e.g. `Haiku=5`) in one file and confirm the consistency check flags the
mismatch.

**Label reason.** Gating — these documents are prompts; a contradiction between the router and a
stage file makes the executing agent's behavior undefined at exactly the load-bearing rules.

## C9 — critical rules stated up front in SKILL.md (advisory)

**Claim.** SKILL.md states the **blindness + read-only + off-limits** rules **up front** (before
the stage table), per the plan's router decision — a position/recency property of the prompt
assembly.

**Verified by execution (document invariant, positive per-site).** Confirm each of the three rules
appears in SKILL.md ahead of the stage table. **Oracle-can-fail self-test:** confirm the check
fails if a rule is absent or appears only after the stage table.

**Label reason.** **Advisory** — placement is a real prompt-quality property (recency/primacy
matters in a position-sensitive assembly), but it is a matter of degree, not a binary
correctness gate; a reviewer can judge "up front enough." Surfaced, not loop-blocking.

## C10 — behavior-preservation for moved/removed content (advisory — N/A greenfield)

**Claim.** Any content *moved or removed relative to a prior version* preserves its behavior.

**Disposition.** **Not applicable — greenfield.** There is no prior version of this skill; nothing
is moved or removed *from* an earlier Data-Distiller. Recorded explicitly (not silently dropped)
so the self-check set is visibly complete. **Advisory**, N/A. (The *internal* position-sensitivity
of the new documents is covered by C9; the porting of brief/charter text *from the sibling skills
and AGENT_BRIEFS* is a fidelity-of-transcription concern the stage-3/6 fidelity lens covers, not a
behavior-preservation-vs-prior-version concern.)

## C11 — agent-facing ledger/brief redaction (gating — added per stage-3 A2/CH8-4)

**Claim.** No **live off-limits / protected path** string appears in any **agent-facing** ledger or
brief the skill ships (the example `examples/companion-emergence/ledger.md` and the `briefs/`
templates). Live protected paths are redacted to a placeholder (e.g. `<REAL-PATH-REDACTED>`), per
decision 8 + issues-log #3 (the frozen ledger citing real protected paths is what tempted the one
real read-boundary crossing).

**Verified by execution (document invariant, positive + normalized absence).** Positive: confirm
the example ledger's off-limits section uses the redaction placeholder where a live path would go.
Absence: after normalizing text (flatten wraps, strip markdown emphasis), grep the agent-facing
ledger + briefs for the known live protected-path patterns from issues-log #3 (`~/Downloads/Phoebe`,
`Phoebes_notes.md`, and any absolute `personas/*` live path) and confirm none appear. **Oracle-can-
fail self-test:** plant a live protected path in a scratch copy of the ledger and confirm the grep
flags it.

**Label reason.** Gating — a shipped example that carries live protected paths reproduces exactly
the issues-log #3 temptation the skill is supposed to design out; it is the cheapest possible check
and guards a real prior incident. (Note: this checks the *artifact is redacted*, which is testable
— not "the agent obeys the read-only clause," which is not.)
