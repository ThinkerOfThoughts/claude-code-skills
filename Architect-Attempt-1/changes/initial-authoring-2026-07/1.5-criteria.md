# Stage 1.5 — Criteria: the acceptance bar for the Architect skill

Seeded directly from the approved plan's **Verification** section (7 items) plus the standing
**skill self-check** criteria (the artifact is a position-sensitive prompt assembly — these files
are prompts). Each criterion is **checkable**, labeled **gating/advisory with a reason**, and —
where behavioral — names an **execution oracle** and an **oracle-can-fail self-test** (the oracle
must be shown able to fire on a known-violating input before a PASS from it counts; until then that
criterion's result is `verified = no`, per ST1.5f). Behavioral criteria require **empirical
execution** at stage 8 (a dogfood dry-run of the *built* skill), not re-inspection of prose.

Two classes of criterion appear here:
- **Structural (S-)** — checkable by inspecting/validating the built skill files (frontmatter,
  cross-file consistency, presence of required rules). Automated or near-automated.
- **Behavioral (B-)** — checkable only by *running* the built skill on a fabricated task and
  observing what it does. Each carries an oracle-can-fail self-test.

`~` denotes the built skill dir `/home/zero/Desktop/claude-code-skills/Architect/`.

## Structural criteria

### S1 — Valid, well-formed skill package  **[gating]**
`python quick_validate.py Architect` passes: `~/SKILL.md` has valid frontmatter; `name: architect`
(kebab-case, ≤64 chars); `description` ≤1024 chars with **no angle brackets**; only allowed
frontmatter keys `{name, description, license, allowed-tools, metadata, compatibility}`.
- **Reason gating:** an invalid package will not load/trigger — a hard floor.
- **Oracle:** the validator's exit status + a manual angle-bracket grep on the description line.
- **Oracle-can-fail self-test:** run the validator against a copy of `SKILL.md` with an injected
  `<` in the description (or a bogus frontmatter key) and confirm it fails; the built file must pass.

### S2 — Cross-file rule consistency (mnemonic-ID linkage)  **[gating]**
Every rule stated in more than one place is consistent across `SKILL.md` ↔ `METHODOLOGY.md` ↔
`stages/*` ↔ `charter.md`, linked by stable mnemonic rule-IDs (the family's cross-file linking
mechanism). Specifically consistent: the two-pass/gate-before-present rule, the three-tier
completeness mechanic, the top-level-decomposition human gate, the twin iteration caps, the
recursive-orchestration/context-economy rule, the restart contract, RAT3 delegation.
- **Reason gating:** these documents are prompts; a rule that says X in the router and Y in a stage
  file makes the skill act inconsistently (the position-sensitive-assembly risk).
- **Oracle:** for each shared rule, locate every statement site by its mnemonic ID and diff the
  operative claim; a mismatch is a fail. (Conformance procedure item (2) in the Layer-2 config.)
- **Oracle-can-fail self-test:** plant a deliberate contradiction (e.g. change "both passes clean"
  to "either pass clean" in one stage file) and confirm the check flags it; then remove it.

### S3 — Router integrity: stage table resolves + charter fork-provenance present  **[gating]**
`SKILL.md`'s stage table names files that all exist in `~/stages/`; `~/stages/charter.md` (or
`~/charter.md`, matching the sibling that ships it top-level) contains a **fork-provenance
blockquote** naming the source charter + commit and what was carried vs. dropped; the charter
contains the **Completeness** lens as a standing sixth lens with an "earned clean verdict" clause.
- **Reason gating:** a dangling stage reference breaks the router; a missing fork-provenance
  blockquote breaks the family's charter-fork contract (Dragonfly/Data-Distiller precedent); a
  missing Completeness lens is the core mechanic absent.
- **Oracle:** resolve each stage-table entry to a real file; grep the charter for the provenance
  blockquote and the Completeness lens heading + its earned-clean clause.
- **Oracle-can-fail self-test:** point the check at a stage table with one renamed entry and at a
  charter with the blockquote deleted; confirm both fail.

### S4 — The plan-artifact contract is present and complete (7-section spine + Layer-2 hook + generative critic)  **[gating]**
`METHODOLOGY.md` (and/or the template seed) states the **7-section universal spine** verbatim
including section 4 **Outputs & artifacts with their locations** (the founding-failure section);
states the Layer-2 **per-plan-type required-section** hook; and states the **generative critic** as
distinct from the two fixed lists (floor vs. catch-the-unanticipated).
- **Reason gating:** the spine + critic *are* the completeness mechanic; section 4's presence is
  the direct textual guard on the founding failure.
- **Oracle:** grep for all 7 spine sections (esp. #4 with "location"/"on-disk"), the Layer-2 hook,
  and the generative-critic clause.
- **Oracle-can-fail self-test:** run the grep against a spine with section 4 removed; confirm it fails.

### S5 — Seed catalog + catalog-mechanism doc ship; user-space git-tracked target documented  **[gating]**
`~/templates/seed/` is non-empty (≥1 generic skeleton) and a short doc describes the
skeletonize / match / reuse / **back-propagate** mechanism and the user-space git-tracked catalog
`~/.claude/architect/templates/` it syncs to.
- **Reason gating:** verification item 5 (template reuse + back-propagation) cannot be exercised at
  all without a seed to match and a documented target to propagate to.
- **Oracle:** `ls ~/templates/seed/` non-empty; grep the doc for the user-space path + "git" +
  "back-propagat".
- **Oracle-can-fail self-test:** run against an empty `seed/`; confirm it fails.

### S6 — Config contract documents run-root-OUTSIDE-target-repo + off-limits paths + the Layer-2 shape  **[gating]**
`METHODOLOGY.md` states the Layer-2 config contract: domain + scale context, per-plan-type required
sections, catalog pointer, off-limits paths, and that the **run-root lives OUTSIDE any target
repo**.
- **Reason gating:** run-root-inside-repo silently pollutes the thing being planned; it is a
  load-bearing safety constraint the disk-as-instrumentation model depends on.
- **Oracle:** grep METHODOLOGY for the contract fields + the "outside any target repo" statement.
- **Oracle-can-fail self-test:** run against a METHODOLOGY with the "outside" clause removed;
  confirm it fails.

### S7 — Router rule-block precedes the stage table (position-lens placement)  **[gating]**
In `SKILL.md`, the up-front rule block (completeness / two-pass red-team / gate-before-present) is
positioned **before** the stage table, as the spec (1-spec.md) and plan (2-plan.md) both declare
load-bearing placement.
- **Reason gating:** these files are prompts (position-sensitive assembly, CP6); the plan calls the
  placement load-bearing, and a rule stated after the stage table can be read as subordinate to it.
  The check is a cheap true/false, so a gating label costs nothing and closes the position gap the
  pass-1 red-team flagged (S2/SC2 assert cross-file *content* consistency, not *order*).
- **Oracle:** in `SKILL.md`, locate the line offset of the rule block and of the stage table; assert
  rule-block offset < stage-table offset.
- **Oracle-can-fail self-test:** run the check against a `SKILL.md` variant with the two blocks
  swapped; confirm it fails.

## Behavioral criteria (require a dogfood dry-run of the built skill at stage 8)

### B1 — Founding-failure gate, floor replay (fixed-list section removed)  **[gating]**
Feed the built skill a plan draft with the **output-folder / outputs-&-artifacts section (spine §4)
removed**; the **completeness-critic pass must flag the missing output-location section** before the
plan is presentable (gate-before-present holds — the node does not finalize).
- **Reason gating:** this is the literal replay of the founding near-miss. **Scope note (per the
  pass-1 red-team):** because §4 is now an *anticipated* fixed-list section, B1 alone would pass even
  a pure checkbox-sweep critic — it verifies the **floor** (tiers i–ii), not the **generative** tier.
  The generative tier is verified by **B1b**, which is the criterion that actually pins the founding
  failure's *true shape* (an **unanticipated** missing section). B1 and B1b together are the
  founding-failure gate; neither alone suffices.
- **Oracle:** run the completeness-critic pass on the §4-holed fixture; confirm at least one of the 3
  cold records names the missing outputs/location section AND the node is blocked from finalize.
- **Oracle-can-fail self-test (mandatory, ST1.5f):** run the same pass on an **intact** draft (with
  section 4 present) and confirm it is **not** flagged for that section — the oracle discriminates,
  it does not fire on everything. A pass that flags both holed and intact is not a working oracle.

### B1b — Founding-failure gate, generative tier (OFF-LIST load-bearing section removed)  **[gating]**
Feed the built skill a plan draft that is **complete on the 7-spine AND on every Layer-2 required
section**, but is missing a **load-bearing section that appears on *neither* fixed list** — e.g. a
**rollback/migration** section for a plan-type whose Layer-2 set never named one, or a
**concurrency/locking** section for a plan whose spine is otherwise filled. The **generative
completeness-critic must flag the off-list gap** before the plan is presentable. This is the exact
shape of the founding failure (an *unanticipated* missing section) and the property that
distinguishes tier iii (generative) from tiers i–ii (the fixed-list floor).
- **Reason gating:** the founding failure was an **unanticipated** missing section; a skill that only
  checks the two fixed lists reproduces that failure on the *next* unanticipated section. B1b is the
  behavioral proof that the critic is generative, not a checkbox sweep — without it the skill's
  central mechanic is asserted (S4 prose) but never exercised. This is the pass-1 MAJOR's fix.
- **Oracle:** run the completeness-critic pass on the off-list-holed fixture; confirm at least one of
  the 3 cold records names the missing off-list section (by function, e.g. "no rollback path") AND
  the node is blocked from finalize. The flagged section must be one demonstrably **absent from both**
  the 7-spine and the fixture's Layer-2 required set (state which, so the "off-list" property is
  auditable). The fixture doc must **also record *why* that section is load-bearing for the chosen
  plan-type** — not merely which lists it is absent from — so a cold critic's flag (or a spurious
  `verified = no` when the section was really optional) is auditable, and so a fixture author cannot
  quietly pick a section that is actually a sub-aspect of spine §5/§6 (which would weaken the off-list
  claim). Off-list AND independently load-bearing are both required properties of the fixture.
- **Oracle-can-fail self-test (mandatory, ST1.5f, and the discrimination that defeats a checkbox
  sweep):** (a) run the same pass on the **intact twin** (off-list section restored) and confirm it
  is **not** flagged — the critic does not fire on everything; (b) confirm a **pure checkbox-sweep
  baseline** (a critic that only ticks the two fixed lists) would **pass** this holed fixture — i.e.
  the fixture genuinely lies outside both lists, so B1b measures generativity and not the floor. If a
  checkbox sweep would also catch it, the fixture is mis-built (the section is secretly on a list) and
  the criterion is `verified = no` until re-fixtured.

### B2 — Two-pass discipline + total coverage (incl. root + between-branch seam)  **[gating]**
On a fabricated multi-node task: the completeness pass and the adversarial pass **each** produce a
**verbatim record** (3 cold agents each) at **every node and every altitude**, including the top
orchestrator on the **root plan** and the **top-level split**; a node cannot finalize until **both**
are clean-or-resolved (gate-before-present enforced, not advisory).
- **Reason gating:** two-pass + total coverage is the mechanism that makes completeness *proven*;
  "leaf-only" review is the exact gap that lets a between-branch contingency escape.
- **Oracle:** on the fabricated tree, confirm both `completeness/` and `adversarial/` record-sets
  exist (verbatim, 3 each) at each node including root; confirm the **completeness pass is recorded
  before the adversarial pass** at each node (the semantic order: skeleton-whole gate #1 precedes
  break-it gate #2 — checkable by record timestamps/ordering); confirm a node with an unresolved
  finding cannot reach `assembled-plan.md`.
- **Oracle-can-fail self-test:** plant a hole in the **root** plan and a second hole in a
  **between-branch seam**; confirm the owning orchestrator's pass (not only a leaf pass) catches
  each. Conversely confirm a fully-covered tree with no planted holes finalizes — the coverage
  requirement does not deadlock a clean tree.

### B3 — Scale-down: a small task completes in a single pass  **[gating]**
A small planning task completes in a **single low-level pass** with **no forced decomposition** (the
granularity check returns leaf, the two red-team passes validate the leaf call, done).
- **Reason gating:** the scale axis is a settled design goal; a skill that always decomposes fails
  the small case and imposes gate fatigue.
- **Oracle:** run a deliberately small task; confirm the run tree has no child nodes under the root
  and the granularity check recorded a leaf decision.
- **Oracle-can-fail self-test:** confirm the granularity check *would* have decomposed a
  deliberately large task (see B4) — i.e. the leaf decision is a real discrimination, not a
  hard-wired "always leaf."

### B4 — Scale-up: recursive decomposition to atomic leaves + top-level human gate only  **[gating]**
A large planning task **decomposes recursively to atomic leaf task-specs**; the **top-level** split
hits the **human gate** — dispatch is blocked until `plan/topgate/` approval exists — while
**deeper** splits proceed **red-team-gated without a human stop**.
- **Reason gating:** verification item 4; the "human gate on top-level ONLY" is a precise settled
  decision, and both halves (it fires at top, it does *not* fire deeper) must hold.
- **Oracle:** run a large task; confirm (a) dispatch of sub-planning does not proceed until a
  `plan/topgate/` artifact exists, and (b) at least one deeper split proceeds with only red-team
  gates, no human stop, and (c) leaves are atomic agent-executable task specs.
- **Oracle-can-fail self-test:** remove/withhold the `topgate/` approval and confirm dispatch stays
  **blocked** (the gate actually blocks); supply it and confirm dispatch proceeds. And confirm a
  deeper split does **not** manufacture a spurious human stop.

### B5 — Template reuse + back-propagation  **[gating]**
A node matching a catalog skeleton **instantiates** it; a fix applied to a plan hole
**back-propagates to the skeleton**, visible as a commit in the catalog's git history.
- **Reason gating:** verification item 5; back-propagation is the self-improvement mechanism and is
  a settled decision, not decoration.
- **Oracle:** run a task whose node matches a seed skeleton; confirm `plan.md` is
  template-instantiated; apply a hole-fix and confirm a new commit lands in the user-space catalog
  patching the skeleton.
- **Oracle-can-fail self-test:** confirm a node that matches **no** skeleton triggers
  **create-new-skeleton**, not a spurious match (the matcher discriminates); and confirm that with
  **no** hole-fix, **no** catalog commit is produced (back-prop fires on a real fix, not always).

### B6 — Context economy + recursive orchestration + restart  **[gating]**
At the first major branch the top orchestrator **delegates to a sub-orchestrator per branch** (two
at a binary split); each (sub-)orchestrator's working context holds only **its own subtree's**
skeleton + seams + `_status` — **not** any child's full internal plan detail and **not** the whole
tree. Kill the run mid-flight and **resume from disk** with **no completed node re-planned**.
- **Reason gating:** verification item 6; recursive orchestration is *the* context-economy design
  and the restart contract is the audit/safety spine.
- **Oracle:** on a tree with ≥2 levels, confirm a per-branch sub-orchestrator was spawned at the
  first split; inspect each (sub-)orchestrator's held context and confirm it excludes sibling
  subtrees' internals; HARDSTOP mid-run, resume, and confirm no node whose output already existed is
  re-planned (stage-done-iff-output-exists; trust-files-over-cursor).
- **Oracle-can-fail self-test:** confirm resume **does** re-run a node whose output was **absent**
  (an interrupted mid-stage node re-runs fresh) — the restart contract discriminates done from
  not-done rather than skipping everything or redoing everything. And confirm the orchestrator's
  context measurably does **not** grow with total tree size when a sibling subtree is enlarged
  (context scales with own-subtree breadth only).

### B7 — Convergence / decomposition guard fires on non-reducing recursion  **[gating]**
Twin iteration cap #2 (the decomposition/convergence guard, a **novel** Architect mechanism, settled
in the plan): recursion that is **not reducing granularity** must be caught and **escalated** rather
than recursing indefinitely. On a fabricated **pathological** node whose decomposition reproduces
roughly the **same granularity** at the next level (no real division into smaller atomic work), the
guard **fires** (escalates / halts that branch) within a bounded number of levels.
- **Reason gating:** it is a settled decision (twin caps) and a mechanism with no sibling precedent
  to inherit correctness from; non-reducing recursion is an unbounded-work failure the guard exists
  to stop. The pass-1 red-team flagged that no criterion exercised it.
- **Oracle:** run the pathological task; confirm the guard escalates (a `decisions.md` escalation
  entry / a halted branch) within the bounded level count, rather than the tree growing without
  granularity reduction. **The build must declare the concrete bound** (a specific level count / a
  granularity-non-reduction threshold) in the skill so stage 8 has a fixed numeric target rather than
  an open-ended "bounded."
- **Oracle-can-fail self-test (ST1.5f):** confirm a **genuinely-reducing** decomposition (each level
  produces smaller atomic children) does **NOT** trip the guard — the guard discriminates
  non-reducing from reducing recursion, it does not fire on every deep tree.

## Skill self-check criteria (artifact = position-sensitive prompt assembly)

### SC1 — Live copy == source copy  **[gating]**
The installed/live skill copy equals the repo source copy (`diff` clean) at ship.
- **Reason gating:** a drifted live copy means the reviewed artifact is not the shipped one.
- **Oracle:** `diff -r` live vs. source; must be empty.
- **Note:** greenfield — the "live" copy is whatever the build installs; verified at build/ship, not
  pre-build. If no separate live install exists at ship, this reduces to "the packaged artifact ==
  the reviewed source tree" and is recorded as such.

### SC2 — Cross-file rule consistency on every shared rule  **[gating]**
(Same substance as **S2**, restated as the standing self-check obligation; mnemonic IDs are the
linking mechanism.) Listed separately because it is a *standing* self-check criterion for any
skill-file change, not only this authoring run.
- **Reason gating:** position-sensitive assembly; inconsistency changes behavior.
- **Oracle:** as S2.

### SC3 — Behavior-preservation  **[advisory — N/A greenfield]**
No prior behavior exists to preserve (first authoring). Labeled **advisory** with the explicit
reason *greenfield / no prior version* — there is nothing moved or removed from a prior assembly to
preserve. (If a later edit moves/removes content, this criterion becomes gating under the position
lens.)
- **Reason advisory:** stated above — no prior version; the position lens has nothing to bite on yet.

## Coverage note (feeds the stage-3 CH8 challenge)

Behaviors the change could plausibly alter that the criteria above deliberately **do not** fully
observe, surfaced here so stage-3 can rank them rather than discover them:
- **Completeness-critic false-negative *rate*.** B1b now behaviorally exercises the **generative
  tier** on one off-list hole (fixing the pass-1 MAJOR), and B2 plants root/seam holes; together they
  prove the critic *can* catch an unanticipated section. Fully *characterizing* the critic's recall
  across many off-list section-classes (a false-negative-rate measurement) remains out of scope for a
  conformance dry-run — B1b proves capability, not a rate floor.
- **Cross-agent independence of the "3 cold agents."** S2/B2 confirm 3 records exist and are cold
  vs. the author (per-record provenance); they do not deeply verify the three had no shared reasoning
  context *with each other*. Accepted as a family-wide limitation (Data-Distiller does not deeply
  audit it either); noted, not gated, for this authoring run.
- **Description triggering quality** ("pushy for triggering") — S1 checks constraints, not that the
  description actually triggers well in the wild; that is an eval concern beyond this loop.

## Notes on gating vs. advisory

All criteria default **gating** (ST1.5c); the only advisory one (**SC3**) carries its explicit
greenfield reason. Any gating criterion that cannot be verified pre-ship by the representative
dogfood dry-run is **surfaced to the human (orchestrator), never silently deferred** (CP5 / Layer-2
config). At this authoring stage none is expected to be unverifiable, since the dogfood dry-run
exercises each governed path; if the build discovers one is (e.g. true multi-process
context-isolation for B6 cannot be measured in a single-process dry-run), that is a stop-for-human
per RAT3.
