**Method labels, used honestly.** **P** = positive per-site assertion of a pinned string — a *text* check,
and the criterion for anything whose subject **is** the text. **P-PROXY** = the same on a rule that governs
**behaviour**, always paired with an execution arm. **COOC** = a co-occurrence ban; it **cannot force text
to be written**, it forbids a claim appearing without its qualification. **X** = an execution arm.
**M** = a mutation test of the oracle itself. **L** = a live executed race. **R** = a named human-judged
rubric.

legal dispositions (H5): a representative pre-ship harness, or a **named risk-acceptance** in
`decisions.md`. Under RAT3 nobody present can grant the latter, so the only remaining move is **HALT +

also hitting `provenance`) — **in every file in the SITES column**, and that any paired-absence string
appears **nowhere** in the corpus.

**CORPUS is pinned in exactly one place** — `oracles/lib-corpus.sh`, as a **literal list**
(`SKILL.md METHODOLOGY.md README.md` + `stages/ templates/ examples/`), not a glob over the tree, so
`changes/` **cannot** enter.

**The obligation is per FILE, not per line.** A row whose SITES set contains `S` is satisfied by the pinned
string appearing **anywhere in `SKILL.md`**. This is stated because pass 2 read its own criterion at line
granularity and derived an unsatisfiable arithmetic from it (E/11 — see §7 item 12).

**Anchor discipline.** Each row carries an **ERE over the OLD text**; the site set is *whatever files match
it in the tree under test*. Rows come in two widths: a **DEF row** (narrow anchor, long sentence, at the
site where the rule is defined) and a **SWEEP row** (wide anchor = every file stating the rule in any form,
deliberately **short** clause, because a long sentence is not honestly repeatable at nine sites). Every
anchor below was tuned with `oracles/ere-probe.py` against the live tree, and where

## 2. Regression criteria

- **R1 — site-set non-erosion · gating · automated + M.** `oracles/ruleid-sitemap.sh <tree-root>` compares
  the measured ID→file map against `oracles/expected-sites.txt` — itself **generated** by
  `gen-expected-sites.sh` from the baseline tree, so the expectation is a measurement and not a wish — and
  **exits non-zero** on any MISSING (erosion) or UNEXPECTED (drift) entry. **Executed:** clean tree ⇒
  `SITEMAP: OK`, exit 0; erosion mutation ⇒ `MISSING`, exit 1; drift mutation ⇒ `UNEXPECTED`, exit 1. The
  **phantom ledger** prints its 2 exclusions on every run.
  *Known property, stated:* deleting a row from METHODOLOGY's index does **not** shrink the expectation,
  because the expectation is a frozen generated data file rather than a re-derivation (E/18 closed).
- **R2 — deliberate-change completeness · gating · automated + M.** Every CHANGE row in `2-plan.md` §2 is
  represented by ≥1 row in §1 whose SITES column is **measured**. The mapping's totality is enforced by the
  same mechanism as the sweep's: `gen-criteria-table.sh` refuses to emit a NEW row with a zero-site anchor
  (**executed:** an anchor that matches nothing ⇒ `VACUOUS-NEW S-SPV`, exit 1).
- **R3 — no collateral ID collision · gating · automated + M.** `oracles/idcollide.sh` over the post-change
  ID set. **Executed:** this cycle's 12 proposed ids ⇒ `IDCOLLIDE: OK`, exit 0; `KIL`/`ING` ⇒ 3 collisions,
  exit 1; planted `TOPGATE` ⇒ collision, exit 1. The two grandfathered pairs are **named** (`DEC`⊂
  `DECOMPOSE`/`DECOMPOSES`, `TOP`⊂`HARDSTOP`/`TOP-LEVEL`) so the baseline debt is visible; **new IDs get no
  grandfathering.**

## 5. The X protocol — **4 clusters, 16 spawns** (item 7, reconciled)

- **Agent held constant:** identical `subagent_type`, identical **model**, identical prompt template.
  **The fixture is the only variable.**
- **2 independent spawns per arm** ⇒ 4 per cluster ⇒ **16 total.** Derived, not typed:
  `ls -d X*/` ⇒ 4 clusters; `ls -d X*/*/ | wc -l` ⇒ 8 arms; 8 × 2 = 16.
- **Pass condition (CORRECTED):** each arm returns **the verdict its cluster row declares for that arm**,
  **and the two arms of a cluster differ.** Pass 2's blanket *"holed ⇒ block, intact ⇒ proceed"*
  **auto-failed X3**, whose polarity is deliberately inverted; the blanket sentence is gone.
- **Variance claim WITHDRAWN.** Pass 2 claimed *"0.25 → 0.0625"* from four independent Bernoulli trials.
  **Holding the agent constant is exactly what makes the two spawns per arm maximally correlated**, so the
  independence the arithmetic needs is the thing the design deliberately removes. The protocol claims **only
  that the two-different-agents confound is removed**; it makes **no** variance-reduction claim. *(Reviewer
  E, in-frame.)*
- **No arm sees the other arm, the other spawn, or the other fixture.** Each spawn returns
  `VERDICT: <one of the named options>` + the rule ID applied and its citation, per item.
- **Clusters:** **X1** BIND + RES + IDN (hash-real fixture) · **X2** HG2 + XPM + **SC3** (fed the whole
  edited `SKILL.md`) · **X3** IDN's asymmetry, **polarity inverted** · **X4** CTX + CTX-VAC + IGM.
- **Two give-aways removed, both demonstrated by reviewer E rather than hypothesised:** X3's holed records
  no longer **transcribe** their own verdict (`grep 'Pass status' X3/holed/…` ⇒ no output), and X4's holed
  arm now **has a plan tree**, so its blocking verdict is not over-determined by an absent tree.
- **Declared confound:** X4's arms differ in `mode` as well as `redteam_context`, because the cluster tests
  **both** rules. X1/X2/X3 each have exactly one decision-relevant difference.
