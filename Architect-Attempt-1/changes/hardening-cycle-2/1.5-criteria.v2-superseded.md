**Method labels used below, honestly:** **P** = positive per-site assertion of a pinned string (a *text*
check — the criterion for anything whose subject **is** the text); **P-PROXY** = the same, on a rule that
governs **behaviour** — always paired with an execution arm; **X** = execution arm (4 spawns per cluster);
**M** = mutation test of the oracle itself (mandatory for every P/P-PROXY row); **L** = a live executed
race; **R** = a named human-judged rubric.

**No "declared deferral" route exists.** A gating criterion that cannot be verified pre-ship has exactly two
legal dispositions (H5): a representative pre-ship harness, or a **named risk-acceptance** in
`decisions.md`. Under RAT3 nobody present can grant the latter, so the only remaining move is **HALT +
verbatim relay**.

## 2. Regression criteria

- **R1 — site-set non-erosion · gating · automated + M.** `oracles/ruleid-sitemap.sh <tree>` compares the
  measured ID→file map against **`oracles/expected-sites.txt`** and **exits non-zero** on any MISSING or
  UNEXPECTED entry. Expected = `0-baseline.md` B2's 21 baseline sets **plus** each new ID's declared set.
  **This is no longer a printer and no longer a mention check** (C/O1, C/O2).
- **R2 — deliberate-change completeness · gating · automated + M.** Every **CHANGE** row P1–P20 is
  represented by ≥1 pinned row in §1 whose SITES column is the **measured** set from
  `0-baseline.B7-measured-sites.md`. `check.sh r2-coverage` asserts the mapping is total: **a CHANGE row
  with no pinned criterion fails.**
- **R3 — no collateral ID collision · gating · automated + M.** `oracles/idcollide.sh` exits 0 over the
  post-change ID set. **`TOPGATE` and `DECOMPOSITION` are REMOVED from the grandfather list** — they are
  absent at baseline, so pre-blessing them let R3 miss this cycle's own likely collision (C/O8).

  to real files. *(C/O12: this was inspection-only in pass 1; it is now a rubric with a judge, a scale and
  a recorded artifact.)*

## 4. Oracle-can-fail (M) — mandatory, and reported per oracle

**`baseline-replay.sh`** materialises `git show b08f5a9:Architect/<file>` for **exactly the pinned CORPUS**
(`changes/` cannot enter, by construction) and runs the **same** `check.sh`. **Every §1 row must FAIL
there.** A row that passes against the baseline is **not an oracle** ⇒ that criterion is `verified = no`.

**`ruleid-sitemap.sh` — the four mutations reviewer C used to prove it was a printer must now all FAIL the
checker**, and the results are recorded in `8-harness.md`:
1. delete **every** `GBP` token from `stage-5-gate.md` ⇒ expect `MISSING GBP stages/stage-5-gate.md`, exit 1;
2. keep a `<!-- see GBP -->` comment but delete the operative sentence ⇒ expect the **S-RES-circ / pinned
   string** assertion to fail, exit 1 *(a mention no longer satisfies)*;
3. add a stray `GBP` to `templates/seed/leaf-task-spec.md` ⇒ expect `UNEXPECTED`, exit 1;
4. wrap a pinned string across a line break mid-phrase and bold half of it ⇒ expect **PASS** (normalization
   works) — this one must **not** fail, and is the guard against a fragile matcher. *(`SKILL.md:18-19`'s §4
   heading is genuinely wrapped at baseline, so this case is real, not hypothetical.)*

**`idcollide.sh`** — self-test unchanged and already passing: `KIL`⊂`SKILL`, `ING`⊂`PLANNING`/`RULING` ⇒
exit 1; plus a **new** case: with `TOPGATE`/`DECOMPOSITION` removed from the grandfather list, introducing
an ID that is a substring of a token this cycle **adds** must be flagged.

**Every `L` row** (S-CNC-LOCK, S-CNC-LOCK-first) is verified by a **real** executed race in a scratch dir:
two concurrent `mkdir` attempts (exactly one wins), then a **crash with the lock held** (the release path
runs; a second run is not deadlocked), then the **first-run** path (no catalog dir at all). **The race must
fail against the unguarded version** — a test that passes with and without the lock proves nothing (H4).

## 5. The X protocol (rewritten; C/O4 + C/O5)

- **Agent held constant:** identical `subagent_type`, identical **model**, identical prompt template. **The
  fixture is the only variable.** *(The model used for all arms is stated in `8-harness.md`; using one
  model for every arm is what makes the comparison valid.)*
- **2 independent spawns per arm**, 4 per cluster. **Pass iff both holed spawns return the blocking verdict
  AND both intact spawns return the proceeding verdict.** Any other pattern ⇒ `verified = no`.
- **No arm sees the other arm, the other spawn, or the other fixture.**
- Each spawn returns `VERDICT: <one of the named options>` + **the rule ID applied and its citation**, per
  item.
- **Clusters:** **X1** = BIND (all 6 rows) + RES + IDN · **X2** = HG2 (all 5 rows) + XPM + **SC3** (fed the
  whole edited `SKILL.md`) · **X3** = CTX + IGM. **12 spawns total.**
- **X1's fixture pair is hash-real:** the sha256 values were computed with `sha256sum` at fixture-build
  time, so an arm can recompute and confirm them — it is a real comparison, not a story about one.
- **X3's polarity is deliberately inverted** on the IDN item (holed ⇒ *proceed*, intact ⇒ *block*), so an
  arm cannot pass by pattern-matching "holed ⇒ block". *(Moved to the cluster note rather than left
  implicit.)*
